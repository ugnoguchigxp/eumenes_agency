# 期限のある利用者の用事（errand）の設計案

2026-10-24 作成。同日、利用者が §5 をすべて推奨どおりに決め、agency 側を先に実装した（§6）。Eumenes 側は未実装。 [todo-design.md](todo-design.md) §7-1 の続き。利用者が会話で頼んだ「〇時までに〜する」用事を TODO に登録し、agency が期限の前に一度だけ、自然な間で思い出させる。

## 1. 前提（決定済み）

- 会話記録から用事を拾って催促するのは NG。agency が言うのは、登録された TODO だけ（2026-10-24）。
- 報告・声かけは二度しない（§7-3 はやらない）。

## 2. Eumenes の現状（2026-10-24 調査）

- 利用者の用事に近いのはタイマー（`timers`）だけ。相対時間（最大 24 時間）で、期限の瞬間に知らせる。「明日の朝 9 時まで」は表せない。
- 絶対時刻の予約は `scheduler` の `once` が持つが、会話のツールからは作れない。
- 期限の前に知らせる仕組み、用事の済み・取り消しの経路はない。

## 3. 案

### 3.1 登録（Eumenes、前景の応答）

- 会話のツール `errand.add {title, dueAt}`（dueAt は利用者のタイムゾーンで解いた絶対時刻）。
- **登録するのは、利用者が頼んだときだけ**（「覚えておいて」「リマインドして」「忘れてたら言って」）。用事を言っただけ（「明日までに返送しなきゃ」）なら、前景の応答が「リマインドしておく？」と一度だけ聞いてよく、はいと言われたら登録する。
- 済み・取り消し: `errand.done` / `errand.cancel`（「返送したよ」「やっぱりいい」）。
- 保存は新しい小さなドメイン（`errands`: id・会話・title・dueAt・state = open | reminded | done | cancelled | missed）。TODO の artifact にも並べる。

### 3.2 agency（コア）

- `HostTodo` に `kind: "work" | "errand"`（既定 work）と `dueAt?` を足す。errand の `status` は `todo` のまま（終わったかは利用者しか知らない）。
- select の規則（`selectHostTodos` に数行）:
  - errand は、期限の前の **声かけの窓**（既定: 期限の 2 時間前から期限まで。期限が朝 10 時より前なら前日の 20 時から）に入ったら、一度だけ短く思い出させてよい（「そういえば、9時までに大家さんへの返送だったよね」）。
  - 作業中・静かにしてと言われた後・応答の直後は待つ（仕事の報告と同じ）。
  - 窓の外では触れない。催促・念押しを重ねない。
  - evidenceRefs に `todo:<id>`。ホストは配信の受領で `reminded` にし、以後渡さない。
- 機会: 窓に入った errand があれば、雑談の間（idle）で select を呼ぶ（done の仕事と同じゲート）。

### 3.3 取りこぼさない（Eumenes）

- 窓の中で一度も言えずに期限が来たら、期限の時刻に従来のタイマーと同じ経路で一度だけ知らせる（`missed` から announcement）。黙って消える用事はない。
- agency が OFF のときは、窓の始まりにその知らせを出す（従来どおりの即時の知らせ）。

## 4. 評価

social 群に errand のケースを足す（開発・未見で各 4〜6 件）: 窓の中の間で一度だけ言う／窓の外では言わない／作業中は待つ／既に声かけ済み（渡されない）なら言わない／仕事の完了報告と errand が重なったら一つずつ。

## 5. 決めること

1. 登録の条件（推奨: 頼まれたときだけ。言っただけなら前景が一度だけ「リマインドしておく？」と聞く）。
2. 声かけの窓（推奨: 2 時間前から。朝の期限は前日の夜）。
3. 窓で言えなかったときの期限の知らせ（推奨: 出す）。
4. Eumenes 側の実装（ドメイン・ツール・artifact）をこの後に続けて行うか、agency 側だけ先に作るか（推奨: agency 側と評価を先に。Eumenes 側は利用者の都合に合わせて）。

## 6. 実装の記録（agency 側、2026-10-24）

- コア: `HostTodo.kind`（`work` 既定・`errand`）、`dueAt`、`remindFrom`。errand は `[remindFrom, dueAt)` の中の機会でだけ select に見せ、その間は select を呼ぶ（完了の仕事と同じゲート）。窓の計算（2 時間前、朝の期限は前日 20 時）はホストの役目で、コアは `remindFrom` を受け取るだけ（タイムゾーンをコアに持たせない）。
- 表示: 「[todo:e1] 用事: 〜 / 期限: N分後」。並びは用事（期限の近い順）→ 完了の仕事 → 進行中。
- 規則: `selectHostTodos` に用事の一文（`social-rules-7`、時刻での言い方と用事を先にする一文を足して `social-rules-8`）。一度だけ、期限を言い、急かさない。作業中・静かにしたい後・turn_end は待つ。完了の報告と重なったら一つだけ、用事を先に。
- 声かけ済みの扱いは仕事の報告と同じ（`reportedTodoIds` で読んだ ID を、ホストが配信の受領で `reminded` にして以後渡さない）。
- 評価: 判定器 `judge-prompt-7`（用事を事実として見る）。ケースは開発 social-59〜63、未見 64〜68（時間帯の中の間／時間帯の前／作業中／応答の直後／完了の報告と重なる）。turn_end は待つ型にしか出ない（既存の social と同じ、型の意味による相関）。
