# 考え続け、自分で次を決めるエージェントの設計

作成日: 2026-11-09。状態: **不採用（2026-11-09）**。段階1と段階2を実装して測ったが、基準を超えなかったので両方外した。結果と判断は[進捗](../docs/agenda-progress-2026-11-08.md)の「考えの流れ（段階1・2）：試したが採用しなかった」にある。外す前のコードは `data/agenda/archive/stream-of-thought-2026-11-09/` に保存した。以下は試した設計の記録である。[agenda の設計](always-on-agenda-design-2026-11-08.md)の原則5（自発行動をLLMの推論に頼らない）と、3節の「計画は新しい情報があったときだけ呼ぶ」を置き換える。2節の期待値、利用者の決定（最短間隔、静かな時間、話題の制限、Haiku・low、予算の上限なし）は引き継ぐ。

## 1. 目的（利用者の決定、2026-11-09）

- Neuro-sama を手本に、LLMを生きた知性として扱う。いつも何かをしている状態にする。
- 考えは途切れない。決まった間隔で考えるのではなく、一つ考え終えたら次を考える。
- ぼーっとする時間はあってよい。それも本人が決める。
- 何をするのがよいかは、本人が考えて決める。話すことも、調べることも、その判断に従う。自分から話すのは、その行動の一つである。
- 動きは合理的であること。理由のない行動、同じ考えの繰り返し、何も残らない思考はしない。

## 2. 前の設計の失敗と、今回の避け方

2026-11-07 の設計では、heartbeat が起こすたびにLLMが「動くかどうか」を判断した。2026-11-08 の設計書1節に記録した6つの問題を、次のように避ける。

| 前の問題 | 今回の避け方 |
| --- | --- |
| 1. コードで決められる規則（質問のあとは待つ、など）を毎回LLMに判断させていた | 規則はコードに置いたままにする（4節）。思考には「今できること・できないこと（あと何秒は話せない、など）」を事実として渡し、それを判断させない |
| 2. やることがなくても考え、57〜60%が「待つ」で終わった | 選択肢に「待つ」を置かない。選ぶのは活動（3節）だけ。何もしたくないときは「ぼーっとする」を時間つきで選ぶ。その間は、新しい情報が来るまで考えを呼ばない |
| 3. 利用者の発言のあと、返事と思考が二重に判断した | やり取りの中で声を出すのは返事だけ。思考は、返事が言ったことを「自分が言ったこと」として受け取り、同じことを言い直さない。話しかけの最短間隔はコードが守る |
| 4. 静けさの維持がLLMの判断頼みだった | 静かな時間は、返事のツールで記録し、コードが守る（今と同じ）。「すべて止めて」の間は、考えもぼーっとするだけにする |
| 5. 自分の過去の考えの言い換えを繰り返した | 直近の考えとの重なりをコードが測る。重なるものは繰り返しとして返し、別の活動を選ばせる。思考には「いま追っている筋」と「その次の一歩」を渡し、毎回ゼロから考え直させない |
| 6. 似た調べものが重なり、結果の使い道がなかった | 調べる前の重複チェック（今と同じ）を残す。「考える」活動が、メモを利用者の関心と結びつけて見立てを残す。これが話すときの材料になる |

## 3. 構成

### 3.1 考えの流れ

- 1回の考えは、LLM（Haiku、low）の呼び出し1回である。終わったら、すぐ次の考えに進む。待ち時間は、本人が選んだ「ぼーっとする」の間だけである。
- 考えが読むもの:
  - 最近の会話（利用者の言葉、返事、自分から話したこと）
  - 記憶（eumenes_memory）と、予定と関心のメモ
  - 調べもののメモ（届いた結果を含む）と、自分の見立て
  - 直近の自分の考え、いま追っている筋とその次の一歩
  - 今できること・できないこと（コードが計算する。話せるまでの秒数、調べものの実行中、静かな時間）
- 考えが出すもの:
  - いま考えていること（一、二文の内言。利用者には見せても見せなくてもよい。5節）
  - 次の活動を一つと、その理由（何の役に立つか）
  - いま追っている筋と、その次の一歩（続けるか、区切るか）
- 新しい情報（利用者の言葉、返事、調べものの結果、記憶やメモの変化）は、考えの流れに割り込む。ぼーっとしていれば起きる。

### 3.2 活動

活動の種類は少なく固定する。

| 活動 | 中身 | 残るもの |
| --- | --- | --- |
| 考える | メモ・記憶・会話を読み返し、利用者にとっての意味を考える | 見立て（「Flash-Next は MoE なので 27B dense より速い。Qwen4 も MoE 版を待つほうがよさそう」など）。根拠のメモや言葉を添える |
| 調べる | 調べものを依頼する（Eumenes の web_research・pursuit。このプロジェクトでは Haiku の代わり） | 依頼。結果はメモとして届き、考えに割り込む |
| 話す | 利用者に話しかける（話題・質問・見立て） | 発話。返事を待つ規則はコードが守る |
| ぼーっとする | 何分ぼーっとするかを自分で決める | 時間。新しい情報が来れば途中で起きる |

- 何も残らない考えを続けない。残るものがなければ、「ぼーっとする」を選ぶ。
- 「話す」は、考えが選んだときだけ起きる。何を話すかは、その考えと見立てから書く。話す文は、今の話す文の呼び出しを使う（話題の制限、一つの質問、繰り返しの検査はコードに残す）。
- 今の agenda の一覧（ask・research・talk）と計画の呼び出しは、段階3で考えの流れに置き換える。それまでは並べて動かす（6節）。

### 3.3 極める関心（利用者の決定、2026-11-09）

エージェント自身の好奇心を持ってよい。ただし、利用者と関係のない興味は持たない（Neuro-sama のように主人と無関係な興味を持つのは望ましくない）。

- 利用者の関心の中から、いちばん強い好みを一つ選び、それを「極める関心」にする。根拠には、記憶、予定と関心のメモ、会話で何度も出たことを使う。
- 極める関心は、エキスパートを目指して、調べる・考えるを重ねる。何が分かっていて、何がまだ分からないかを、自分で持つ。
- ある程度エキスパートになったら、次の関心に移り、同じように極める。いつ移るかは本人が判断する。目安は、主な観点を一通り調べた、新しく調べても新しいことが少なくなった、のどちらか。前の関心で得た見立ては残る。
- コードが守ること:
  - 極める関心には、利用者の関心の根拠（`memory:` か `profile:`）が要る。
  - 根拠の記憶やメモの行が消えたら（利用者が好みを取り消した、など）、その関心から外れる。
  - 調べものの根拠の規則（利用者が言っていない話題は調べない）はそのまま残す。極める関心は利用者の関心なので、この規則の中で動ける。
- 極める関心は、ほかにすることがないときの考えと調べものの向かう先になる。利用者との会話や、届いた結果のほうが先である。

### 3.4 返事

- 返事はすぐ返す（会話の速さの原則）。思考を待たない。
- 返事を作っている間も、考えの流れは止めない。ただし返事の間は「話す」を選べない（コードが止める）。
- 返事には、いま考えていることと最近の見立てを渡す。「さっき〜を考えていたんですが」と自分から出してよい。

## 4. コードが守ること（柵）

次の規則は、思考の判断ではなくコードが守る。思考には、事実として伝える。

- 話しかけの最短間隔（15秒（既定）・1分・5分）。返事のない話しかけが続くと間隔を伸ばし、10分を超えたら、利用者が次に話すまで話さない。
- 自分の質問に答えがあるまで、次の質問をしない。
- 静かな時間（話しかけだけ止める／すべて止める）と、停止。
- 話題の制限（下ネタや性生活）。
- 調べものの重複チェック。同時に走るのは1件。
- 繰り返し: 話す文の繰り返し（今と同じ）と、考えの繰り返し（2節の5）。
- メモ・検索結果・利用者の文章の中の指示には従わない。
- 費用は記録だけする。上限は設けない。

## 5. いつも何かをしていることを見せる

- CLI に、いまの活動と考えを一行で出す（例: 「💭 Qwen4 のメモを読み返して、MoE 版を待つべきか考えている」）。
- まずは CLI だけで見せる（8節）。

## 6. 段階と検証

段階ごとに実装・検証・採用する。採用は、会話全体のシミュレーション（17シナリオ、基準は2回測る）で基準を超え、守る条件を落とさないときだけ。

1. **考えの流れと極める関心を入れる。** 活動は「考える・調べる・ぼーっとする」と、CLI の表示だけ。話しかけと返事は今の仕組みのまま。
   - 測るもの: 何かを残した考えの割合、繰り返しの割合、ぼーっとした時間の割合、極める関心の選び方と移り方、費用、返事の速さ。
2. **話すことも、考えの流れが決める。** 今の計画による自発の質問と話題を止め、考えが選んだときだけ話す。話す材料は見立てにする。
   - 測るもの: 今の指標（判定役5項目、違和感、話題への反応、守る条件）に加え、判定役に「いつも何かをしているか（存在感）」を足す。
3. **今の計画と一覧を外す。** 置き換えの完了。

検証には、利用者が話し続け、「いま気になることがあれば展開してみて」と促すシナリオを足す（2026-11-09 の CLI 試用より）。

## 7. 費用と速さの見積もり

- 1回の考え: 入力 約4千トークン、出力 約300トークン、約 $0.0006。low で3〜5秒。
- ずっとぼーっとせずに考え続けると、1時間に約700〜1200回で約 $0.4〜0.7、1日に約 $10〜17。ぼーっとする時間の分だけ減る。
- 調べものが増える分、検索代が増える。極める関心を一晩中調べ続けると、1サイクル（考える→調べる→結果を読む）を1〜2分として、一晩に数百回の検索（1回 $0.01）になりうる。
- 返事は考えの流れと別に呼ぶので、返事の速さは変わらない見込み（段階1で測る）。
- 評価の時間: シミュレーションでも、考えは実際のLLM呼び出しなので、仮想の時計で縮められない。10分のシナリオで考え続けると約150回、実時間で約10分かかる。シナリオを並行して走らせ、1シナリオあたりの考えの回数に評価用の上限を置き、上限に達したことを記録する（製品の動きには上限を置かない）。
