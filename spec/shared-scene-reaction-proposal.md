# その場限りの反応をどう扱うか

2026-11-04の設計案。実装前の検討事項。

二人で見ていた展示の全景が現れたとき、「青い鳥になっていたんですね」と気づきを共有する。一言伝えれば用は済む。通常応答ですでに触れた場合、相手が静かに見ている場合、別の展示へ移った場合には、あとで言い直す理由もない。一方、「なぜこの材料を使ったのか調べたい」という問いには、後で戻ってくる意味がある。

## 推奨案

前者は**今回の発話機会にだけ選べる反応**として、既存の参加判断で扱う。ホストは、どの会話で何が共有されたかを観測として記録できたとき、その観測の参照を渡す。モデルが直前の会話、通常応答、自分の直近の発言、いま話す負担を読み、発話か待機を選ぶ。単発の反応のために親の意図や継続的な関心を作らない。

後者は既存の意図と候補で扱う。共有した出来事がきっかけでも、調査を選ぶなら、根拠・利用できるツール・実行権限・予算の検証を通す。何が一言で済むか、何が残る問いかはモデルが文脈から判断する。

## 入力から配信まで

1. ホストは会話と場面が一致する共有観測のIDを、その機会の入力に含める。共有されたことを確認できない画面情報は渡さない。現在の本体でどの表示変化を観測できるかは、接続先ごとに確認する。
2. Agencyは対象IDを機会の開始時に固定し、更新と選択に同じ根拠を渡す。現行の処理では先行する状態更新が新着観測を処理済みにするため、選択時の新着一覧だけに依存しない。継続候補が空でも、この機会に有効な共有観測があれば選択できるようにする。
3. 短い反応として発話するなら、モデルは今回提示された共有観測を明示して本文を返す。実行側は参照の所属・有効性を検証し、既存の発話チケットで配信する。配信直前にも対象会話・割込み・未回答上限を確認する。
4. 待機なら、単発の話題を持ち越さない。配信前に場面が変わった場合はその反応を取り消す。音声側への引き渡し後は、提案済みの観測を識別できる形で記録する。再生結果が不明なときも同じ一言を自動再送しない。

既存の意図を配信成功だけで一律に完了させる変更は避けたい。「調べる」と言えたことが、その調査を終えた証拠になってしまう。その場で済む発話に限って状態を作らない方が、仕事の完了条件を保てる。

## 採用前に確かめる場面

| 場面 | 観測する結果 |
| --- | --- |
| 二人が見ているものが変化し、通常応答はまだ触れていない | 根拠のある一言を配信できる。配信後に未完了の意図が増えない。 |
| 同じ変化だが、利用者が静かに見たいと伝えた、または通常応答で言い終えた | 待機でき、その出来事だけを理由に後続の無音時に再提案しない。 |
| 選択中に会話や場面が変わった | 古い反応を配信しない。 |
| 音声側へ渡した後、再生確認前に次の機会が来た | 提案した内容と元の観測を識別でき、聞こえたとは断定しない。 |
| 同じ出来事から後で調べる価値のある問いが生まれた | 通常の調査候補として扱え、結果が返るまで仕事は未完了のまま。 |

最初の受入範囲は、本体で実際に観測できる一種類の共有イベントに絞る。実モデルでは、同じ出来事について「一言が自然」「静かに見たい」「すでに話した」を対にして確認する。固定試験では配信先、期限切れ、重複、開いた意図の件数を確認する。
