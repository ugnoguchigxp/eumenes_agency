# 研究根拠と、この計画への適用範囲

確認日: 2026-10-21。論文の主張・本計画の推論・未検証を分ける。以下は12件の一次資料と1件の参考実装であり、網羅的な系統レビューではない。発表時のモデルや用途に限定された結果を、2026年のモデル全般や日本語音声会話の性能へ一般化しない。数値の横並び比較は行わない。

## 2. 根拠から採用する設計判断

次は論文の結論をそのまま適用したものではなく、本プロジェクトへの推論である。合否は[検証計画](verification-plan.md)で確かめる。

| 判断 | 根拠 | 反証・変更条件 |
| --- | --- | --- |
| 候補の保持と表出を分ける | R01、R06 | 指示＋想起と同じ有用性なら、複雑な候補形成を縮小する |
| 意図には維持・撤回条件を持たせる | R05、利用者指示が優先という既存契約 | 保留状態が戻らない／拒否後も再提案するなら、入力と再検討契約を見直す |
| 初期は最小台帳で始め、好み・感情状態を後置する | R02–R05は本製品の各状態の必要性までは示さない | 状態を分けた条件だけが未見ケースで改善した場合、該当状態を追加する |
| 時機・内容・受容・効果を別に測る | R06–R09 | モデルjudgeの点数だけ向上し人の負担が増えるなら不採用 |
| 結果と反証を使い、自己出力を独立証拠にしない | R10–R11、既存のreceipt設計 | 同じ根拠の言い換えで確信や意図が増殖するなら更新案の契約と提示情報を修正する |
| 保存された解釈も低信頼資料として扱う | R12、既存のreference分離 | schema合格でも注入由来の目標を採用するなら、意味評価・出所提示・権限境界を再検証する |

## 3. 代替案と、今回まだ分からないこと

| 案 | 得られるもの | 負担・未確認 |
| --- | --- | --- |
| 現行の応答＋Memory/World（B0） | 最も小さな追加コスト。利用者が明示した時の想起 | 自発的な再開を目的としない。これだけとの比較では追加機構の必要性を証明できない |
| 指示＋同じ想起＋機会ごとの選択（B1） | 既存機構中心で自発提案できる比較対象 | 保留した意図をどれだけ復元できるかは実測が必要 |
| 最小の意図・候補台帳（B2） | 根拠、再開/完了条件、配信履歴を永続化 | 欲求や状態を別概念に分けなくても十分かを調べる |
| 分離したbelief/desire/goal（F） | H1–H4を明示的に表現する候補 | 状態数、依存閉包、token、修正負担が増える。B2以上の効果は未立証 |

全条件で権限・取消・receiptの安全なホスト境界は共通にする。研究システムを製品の代替として直接導入する比較ではない。

未確定なのは、実際に困っている場面の頻度、利用者が望む自発性、最小台帳に対する分離状態の利点、必要なモデル能力、長期の変化、日本語音声の負荷である。文献数を増やすだけでは解消できない。次は利用者の場面選択、実モデルの予備比較、許可された実会話の順で根拠を増やす。単一利用者の結果から一般利用者への有効性は主張しない。
