# 仮想EumenesとMemory連携の検証・俯瞰レビュー

**追加レビュー後の実装順は[ホスト入力の出典契約と本流互換の仮想結合計画](../spec/host-input-provenance-2026-11-06.md)を正本とする。** 以下は先行した保存接続・測定の計画と実施記録。これらの成功を、本流F・独自指示・話題・TODOによる忘却後の継続確認へ広げない。

目的はAgencyの完成度を高めるため、実際のMemory公開APIとの接続を先に確かめ、責務の重複と行動品質の失敗を俯瞰してレビューすること。独自Memoryを本番へ採用しない。CI・本流取り込み・commit/push・別チャットへの送信は行わない。Memoryリポジトリと本体のソース・DBは変更しない。

## 範囲と再利用

`examples/virtual-eumenes`へ、Bun SQLite上の仮想ホストを置く。Eumenesが採用するMemory 0.0.2 / schema 8の配布物SHA-256を固定し、公開APIのみ使う。原観測本文はRecordsを正本とし、Agency側にはcheckpoint、観測IDとSourceRefの対応、全入力依存を保存する。意味判断は既存LLM更新・選択、整合性と失効は既存Agency coreを再利用する。standalone/CheckpointStoreの機能拡張はしない。

Memoryのcapture/read、外部依存登録、変更フィード、forget/reconcile/receiptを接続する。Memoryの上限による分割は件数制約への対応に限り、意味分類を追加しない。書込みは同一DB・同一transaction。忘却journalはDB外へ先行保存し、復元後はqueue起動前に再適用する。失敗・拒否・削除未確認を成功として扱わない。

## 作業順と完了条件

1. 変更前のコード・費用・既存検査結果を固定する。
2. 公開APIの部分試験：配布物のhash、migration、capture/read、scope、依存登録の拒否、forget receipt。
3. adapter結合試験：原文の二重保管を避ける、再起動、古い引用、非引用入力の忘却、派生観測と実行票の削除、journalによる古いDB復元の遮断、transaction失敗時の未確定結果の非公開。
4. 同じ合成入力・同じ保持条件で、原文参照の可用性、本文保持量、再起動と忘却、ローカルp95を比較する。決定的試験は行動品質の証明としない。必要なら固定後の小さいAPI比較を別結果として測り、これまでと同じ累計台帳・9ドルの実行制限で10ドル以内を保つ。
5. Agencyの入力→更新→選択→実行票→結果→保存/復元、権限・予算・取消、SystemContext、配布・テスト・設定を俯瞰する。確認済み・疑い・反証済みを分け、再現条件と改善順を記録する。今回は技術レビューで、将来性を合算した新しい評点は作らない。
6. Memory起因と断定できる不具合は、配布物の版/hash・単独再現・期待/実際・影響・受入試験を持つ改修依頼ファイルへまとめる。Agencyの接続ミスやMemoryの明示的なホスト責任を、Memoryの欠陥として報告しない。送付はせず、このリポジトリへ保存する。
7. 部分→結合→ローカル通し検査、差分とLLM-Native原則の点検、READMEと残作業の更新まで行う。

単体80点超えは引き続き未達。新adapterや試験件数だけでは加点せず、以前の行動品質の率・安全・費用の合格条件を維持する。未解決の重要問題を無視して80点としない。同じ目的の試行3ラウンド後は、証拠・残作業・仮説を見直してから続行する。

## 実施結果

仮想adapter、Memory公開APIの接続、部分・結合試験、ローカル通し検査、4ケース×両条件×両providerのAPI比較と無料再生を実施した。原文保管はMemoryへ一本化し、独自standalone保存は本番不採用と明記した。Memory由来の確定不具合はなく、改修依頼は作成していない。Agencyの再開・読み戻し・指示の問題を再現して[俯瞰レビュー](agency-review-2026-11-06.md)へ記録した。このレビューのための接続実装と測定は完了し、80点超えに必要なAgency側の修正と正式な行動評価は残作業とする。
