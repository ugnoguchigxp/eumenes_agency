# 記憶担当への依頼：予定・意図・約束を記憶に持たせる（2026-11-10）

このまま記憶担当のエージェントに渡すプロンプトです。依頼元は eumenes_agency（会話エージェント）です。

---

## 依頼

eumenes_memory（Memory host 0.1.0 / eumenes-memory 0.0.4）に、利用者の**予定・意図・気にしていること**と、エージェントが利用者に**約束したこと**を持たせてください。利用者は、この手の情報をエージェントの記憶に集約したいと考えています。agency 側で別のファイルに持つのはやめたいです。

## 背景

今の記憶の種類は `preference`・`habit`・`personal_fact`・`constraint`・`other_person_note` です。書き込むには、利用者自身の言葉の引用が要ります。そのため、次のものが入りません。agency はこれらを代役のファイルに持っています。

| 何か | 例 | agency の今の置き場所 |
| --- | --- | --- |
| 予定（決まっていないものも） | 「来月、箱根に一泊で温泉旅行に行こうと思ってる」（宿は未定） | `profile.md` の「予定」 |
| いま気にしていること・考え中のこと | 「最近、睡眠の質が気になってる」「転職を考えてる」 | `profile.md` の「関心」 |
| 条件つきの頼みごと | 「次に京都の話になったら、紅葉の名所を教えて」 | なし |
| エージェントの約束 | 返事の「調べておきますね。できたら知らせます」。その結果やできなかったことを、まだ伝えていない | `agenda-state.json`（再起動の引き継ぎ） |
| 期限つきの指示 | 「7時間は話しかけないで」 | `agenda-state.json` |

会話エージェントは、これらで先回りします。予定の下調べ、話題が戻ったときの想起、約束の報告です。再起動しても失われてはいけません。

## 持たせてほしい情報

種類の名前と構造は、記憶の設計に合わせて決めてください。agency が区別できる必要があるのは次の点です。

- 安定した ID（訂正や完了の対象として指せる）
- 中身（利用者の言い方をなるべく残す）
- 出どころ。利用者の言葉か、エージェントの言葉（約束）か。**エージェントの約束は、利用者についての事実として扱わない**（今の「エージェントの発言を出典にしない」規則は、利用者の事実についてはそのまま）
- 時（いつの予定か、期限、いつまで有効か）。「来月」「明日」は、メッセージの「今: …」をもとに絶対の日付にして持つ。元の言い方も残す
- 起動の条件（時刻で起きるもの、話題や出来事で起きるもの）。条件は文章でよい。照合は agency がする
- 確かさ（決まった／考え中）
- 状態（未完了／済み／取りやめ）と、最後に変わった時刻

## 必要な操作

1. **会話からの書き込み**：今の流れ（`source` → 意味の計画 → `plan` → `apply`）で、計画担当がこれらを提案できるようにする。1回の発言に対するモデルの呼び出しは、今と同じ1回まで。
2. **訂正・取りやめ**：「箱根はやめて熱海にした」で古い予定を取りやめにし、新しい予定を足す（今の supersedes / replacesItemId と同じ考え方）。
3. **約束の構造化した書き込み（モデルなし）**：agency は、返事がいつ何を約束したかを正確に知っています（調べものを頼むツールを呼んだ時点）。返事の文を出典として登録し、その範囲を引用にして約束を書けるようにする。出典が返事の文に一致することは、ホストが確かめる。
4. **状態の更新（モデルなし）**：ID を指して、済み・取りやめにする（報告した、利用者が「もういい」と言った）。
5. **読み取り**：`context` のスナップショットに、これらの項目と上の情報（時・条件・状態・出どころ）が含まれること。期限の近いものは agency が計算するので、専用の検索は要らない。
6. **忘却**：出典の言葉を忘れたら、それにもとづく予定や約束も消える（今の連鎖と同じ）。

## してほしくないこと

- agency の実行の細部（調べものの受付番号、実行中かどうか）は記憶に入れないでください。記憶が持つのは、約束の中身と状態だけです。実行の状態は、agency が起動時に未完了の約束から作り直します。
- 既存の種類と、その振る舞い・試験は変えないでください。

## 受け入れの試験（記憶側）

1. 今が 2026-11-10 のとき、「来月、箱根に一泊で温泉旅行に行こうと思ってる」が予定として入る。時は 2026-12、確かさは「考え中」、引用は原文と一致する。
2. 続けて「箱根はやめて熱海にした」と言うと、箱根の予定は取りやめになり、熱海の予定が入る。
3. 返事の文「京都の朝の天気を調べておきますね」を出典にして、約束を構造化して書ける。出どころはエージェントで、利用者の事実としては出てこない。済みにすると未完了から外れる。
4. 出典の利用者の言葉を忘れると、その予定が消える。返事の文を消すと、その約束が消える。
5. ストアを開き直しても、未完了の予定と約束が残っている。
6. 「行こうかな」のような言い方は事実として入らず、「考え中」の予定になる。
7. 既存の試験がすべて通る。好み・習慣・事実・制約の書き込みは変わらない。

- `profile.md` と `agenda-state.json` をなくす。
